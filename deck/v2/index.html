03  The feedback loop

The loop only closes where the data lives

A system improves by learning from its own outcomes — record, decide, act, observe, record again. When the record lives in someone else's cloud, the loop belongs to someone else.

A memory that stays

Outcomes, corrections and exceptions remain with the entity, so every decision is measured against the last one.

A jury, not an oracle

Several models read the same evidence. Agreement confirms; disagreement is where a person looks.

A corpus no one else has

The private record — claims, calls, outcomes — that no foundation model has seen and no vendor could be given.

Intelligence should be plural. Governance is not the tax on the loop — it is what closes it.

08  The team

Lightweight teams, heavy infrastructure

A small team should not have to hire infrastructure engineers to move quickly. The infrastructure should arrive already operating.
Telemetry→ Threshold rule fires→ Model decides — allowlist only→ Audited LXD execution→ Audit row

1 It watches

Thresholds on memory, disk and inference health. The loop runs whether or not anyone is awake, and a rule — never a model — is what notices.

2 It decides, inside a cage

The model chooses among allowlisted actions; grammar-constrained decoding makes anything else unencodable, and the deterministic fallback is always available.

3 It leaves a receipt

Every autonomous change links trigger → decision → action → result in one audit record, so a small team can prove what happened without having watched it.

The small team, with serious infrastructure behind it.

09  How it lands

Delegate the operations, not the data

Bootstrap, remediation, upgrades, the on-call rotation. The operations. This is the work a twelve-person firm cannot staff and a hardware owner does not want to build.

11  Technical · the architecture

The architecture is the governance claim

Node on premises→ On-node redactor→ Outbound-only mTLS→ Controller gate→ Operator loop→ Audit chain

Substrate and channel — adopted, not invented

Ubuntu and an LXD cluster across nodes; one outbound-only mTLS WebSocket per node carrying heartbeat, telemetry, commands and acks. No inbound path from the internet, and no route from an agent VM to the controller.

Boundary and loop — the two things we build

A fail-closed telemetry gate that rejects a non-conforming batch rather than dropping fields, and a governed operator loop: detect → decide inside an allowlist → execute against LXD → write the audit row.

12  Technical · the boundary

What leaves the building, exactly

ClassLeaves?Contents
C0Yes — allowlistedHardware and OS health: CPU, RAM, disk, GPU, inference liveness, instance inventory, rule metrics
C1Yes — transformedSalted hashes, bounded display labels, timestamps. Never raw identifiers
C2NeverWorkload payloads, call transcripts, patient or customer records, prompts, credentials, logs

The one external call — disclosed

The operator's diagnosis runs on Gemini via Vertex AI from the controller's loopback listener. Prompt: C0 telemetry only. The audit row records egress=external. One variable, backend=local, puts the same decision back on the node's own weights.

Why we publish the exception

Because a boundary you cannot see is not a boundary. The claim is not “nothing leaves” — it is “nothing C2 leaves, and everything that does is named, classified and audited.”
