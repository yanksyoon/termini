06  The inversion

Intelligence should be plural

Today: one model, everyone's data

One answer for everyone · value accrues to the model owner · shared blind spots · the entity's own context is the raw material, and it is spent.

Inverted: one model per entity

Its own data, its own answer · value accrues to the entity · different priors, so disagreement becomes signal · the context compounds instead of leaking.

More useful

A 4B model that has read twelve years of your claims beats a frontier model that hasn't. The marginal token of general intelligence is worth less than your context in the loop.

More reliable

Centralisation correlates failure: same weights, same blind spots. A population of sovereign models is a portfolio, and a jury beats an oracle.

More shareable

Evals, weights and lessons can travel between entities. Records don't have to. That is what enriching the ecosystem actually means.

10  The product · day-2

The part the dentist had to become

Telemetry→ Threshold rule fires→ Model decides — allowlist only→ Audited LXD execution→ Audit row

1 Detect deterministically

A threshold rule fires. Never a model. Rules are the detector; the model is only ever the decider — so the loop works even when the model doesn't.

2 Decide inside a cage

Grammar-constrained decoding: an off-allowlist action has no valid encoding. Plus parameter guards, a confidence gate, and a mandatory deterministic fallback.

3 Prove it afterwards

Every autonomous change links trigger → decision → action → result in one audit record. “The AI did it” becomes a row you can read.

Ownership without the ops burden — the only version of on-prem a twelve-person firm can survive.

13  Technical · the architecture

The architecture is the governance claim

Node on premises→ On-node redactor→ Outbound-only mTLS→ Controller gate→ Operator loop→ Audit chain

Substrate and channel — adopted, not invented

Ubuntu + an LXD cluster across nodes; one outbound-only mTLS WebSocket per node carrying heartbeat, telemetry, commands and acks. There is no inbound path from the internet to a node, and no route from an agent VM to the controller.

Boundary and loop — the two things we build

A fail-closed telemetry gate that rejects a non-conforming batch (422) rather than dropping fields, and a governed operator loop: detect → decide inside an allowlist → execute against LXD → write the audit row.

Bootstrap

Pre-baked image, single-use enrolment token, CSR → client cert, role assigned, cluster joined. 150 ms.

Placement

Natural language → structured allocation → guardrail clamp → real LXD instances, rolled back on failure.

Access

A controller-held SSH CA: browser-generated keypair, ≤8h principal-bound certificate. No shared keys.

The node keeps the data. The controller keeps the proof. That is the whole design.

14  Technical · the boundary

What leaves the building, exactly

ClassLeaves?Contents
C0Yes — allowlistedHardware and OS health: CPU, RAM, disk, GPU, inference liveness, instance inventory, rule metrics
C1Yes — transformedSalted hashes, bounded display labels, timestamps. Never raw identifiers
C2NeverWorkload payloads, call transcripts, patient or customer records, prompts, credentials, logs

The one external call — disclosed

The operator's diagnosis runs on Gemini via Vertex AI from the controller's loopback listener. Prompt: C0 telemetry only. The audit row records egress=external. One variable, backend=local, puts the same decision back on the node's own weights.

Why we publish the exception

Because a boundary you cannot see is not a boundary. The claim is not “nothing leaves” — it is “nothing C2 leaves, and everything that does is named, classified and audited.”
