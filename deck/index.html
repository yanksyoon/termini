06  Spec question 1 of 4 — resolved
Q1What operations scenarios do we showcase, and how do we simulate them?
ResolvedTwo real failures, two real fixes — A: out-of-memory and B: disk degradation — simulated with off-the-shelf tools, so a judge sees the exact failure a production customer would.

A Out-of-memory

stress-ng burns RAM, starves neighbor agents → operator detects, resizes the offending VM, restores the fleet.

B Disk degradation

Injected I/O error (write latency climb / read-only mount) → operator flags the drive, drains the node, alerts the user.

Contested: beating the kernel OOM-killer is best-effort. Resolved with 1000 ms telemetry + a local fast-path (no model latency) + a synthetic persistent trigger — we demonstrate the detect → decide → execute → audit loop deterministically.
How the demo proves it — dashboard shows RAM crossing 95% → a vm.resize acks succeeded → new ceiling visible, traceable end-to-end in the audit log.

07  Spec question 2 of 4 — resolved
Q2What cloud system ties the nodes together — LXD or OpenStack — and how do they share a network?
ResolvedLXD (5.21/stable) as a 3-member cluster. OpenStack rejected — hours-to-days of setup for problems this demo doesn’t have.

▦ Networking — no overlay

Each node keeps a local NAT bridge on its own subnet; cross-node traffic rides the physical underlay by real IP. GPU inference is reachable at http://10.10.0.13:8080.

◈ No tunnel to misconfigure

A single static route either works or it doesn’t — no encapsulation. Guest MTU clamped to the underlay (1460) to avoid PMTU black holes.

Contested: overlay tunnels (OVN/Fan/VXLAN) silently drop packets on MTU mismatch and add per-call latency. Resolved by removing the tunnel entirely.
How the demo proves it — from an agent VM on Node A, curl http://10.10.0.13:8080/v1/models returns the model list over standard HTTP; watch traceroute and streamed tokens with no tunnel in the path.

08  Spec question 3 of 4 — resolved
Q3How do we smartly allocate agent-VM resources — can we infer them from natural language?
ResolvedYes. Plain English → intent extraction (on-prem, grammar-constrained JSON) → deterministic validator. The model recommends; the validator decides.

✓ Hard caps

  • vcpus ≤ 128, ram ≤ 512 GB, count ≤ 64
  • Per-node ceilings with host reserve
  • Per-type ranges (agent_vm: vcpus 1–8, ram 1–16 GB)

✕ All-or-nothing

  • Numbers are clamped to real capacity
  • Structural violations rejected outright
  • A rejected class creates nothing
Contested: a prompt like “super fast agent” yielding vcpus:128, ram:512 that LXD can’t honor. Resolved with deterministic hard guardrails, not model politeness.
How the demo proves it — type “128 vCPU, 512 GB RAM worker” → the plan shows clamped values within the host’s real capacity, with per-field from → to clamping visible in the audit record.

09  Spec question 4 of 4 — resolved
Q4How do we serve the pre-baked agentic OS — what’s pre-installed, and how do we hand it over AI-ready (SSH-able)?
ResolvedImmutable pre-baked images — nothing downloads at boot. cloud-init only activates & registers in <5s. Access is browser-first.

◈ Access without passwords

  • Browser generates the keypair locally
  • Controller signs a short-lived cert (≤8h)
  • One-click web terminal + an ssh string
  • No shared private key — one leak can’t compromise the fleet

▣ Data boundary (C0/C1/C2)

  • Only C0 hardware/OS telemetry + C1 transformed IDs egress
  • C2 (logs, payloads) never leaves
  • On-node redactor fails closed before the socket opens
  • External model calls scoped to C0 only
How the demo proves it — power on → registered <5s with zero installs; open the terminal for a passwordless shell; pull the governance audit and show zero C2 records, every call traceable by its call_id.
