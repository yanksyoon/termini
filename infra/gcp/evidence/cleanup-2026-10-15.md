## 0. Why: "instances terminated" is not "no cost"

On 2026-10-15 every instance of the footprint was TERMINATED and Cloud Run had
scaled to zero, and the project still billed **$37.77/mo**: 210 GiB of
pd-balanced disks $25.20 + 60 GiB of node images $3.60 + the static IP
`termini-controller-ip` $8.76 (billed as in-use while associated with an instance,
running or stopped) + the 10.37 GiB model bucket $0.21. After the two superseded
images were deleted the same day the idle floor is $35.37/mo. The enumerator in §1
is what makes that surface visible instead of assumed.

## 7. The log-bucket case, and the survivor detector firing

Round 1 of the throwaway testing (earlier revision, kept here for its content)
created a `termini-verify-logbucket` as well, and the run **exited non-zero (2) and
named the survivor** instead of printing "clean" — which is the property the card
asked for. The `describe` output shows why: the Logging API moves a bucket with
retained logs to `DELETE_REQUESTED` and reclaims it when the retention window
closes, and no gcloud lever removes it sooner (`gcloud logging buckets delete
--recursive` does not exist in SDK 588.0.0 — `unrecognized arguments: --recursive`,
captured below). The shipped scripts now classify that state explicitly as *pending
finalization* (a distinct row, not a survivor, and not a false "clean").

## 8. Deviations, limits, and what was NOT verified

1. **`DELETE_REQUESTED` log bucket**: a log bucket with retained logs cannot be
   removed instantly. `teardown.sh --full` issues the delete, the API accepts it and
   the bucket moves to `lifecycleState: DELETE_REQUESTED` until its retention window
   closes; the scripts report that state explicitly (0 in-remit, exit 0) and
   `cleanup-verify.sh` prints it as its own row. This is an API contract, not a
   leftover in the classes the card asked about — instances, disks, images,
   addresses, buckets and registry repositories were all verified at zero.
2. **`_Default` / `_Required` log buckets are retained by contract**: both are
   Google-managed and cannot be deleted (`_Required` is `locked: true`, 400-day
   retention). Reported with that reason. Their storage is reported as
   `size=unknown` because **Cloud Logging exposes no size instrument** — an honest
   "could not verify", never a fabricated 0.
3. **Quota preference records are opt-in** (`--delete-quota-preferences`, default
   OFF): they are not billable, and `termini-cpus-all-regions` carries the granted
   `CPUS-ALL-REGIONS=12` the fleet's vCPU budget depends on. Deleting that record to
   tick a box could break the fleet's ability to be raised.
4. **VPC / subnet / firewall rules are kept** unless `--include-network` is passed:
   they are not billable.
5. **No live Cloud Run service was created for the throwaway round** (that needs a
   container image in the registry, i.e. a build just to delete it). The Cloud Run
   path is exercised in the real project's dry run (§2) and the Artifact Registry
   path — create, drain-if-non-empty, delete, confirm gone — was exercised live;
   revisions are enumerated, including `termini-gemma-00001-ql5`.
6. **No engine ever saw the bill.** The instruments here are API enumerations plus
   the sizes/rates measured on 2026-10-15. The Cloud Billing report / BigQuery
   export as the ground-truth instrument belongs to the verifier card `t_6208533e`;
   this evidence does not claim it.
7. **The demo set (4 disks, the image family, the bucket, the reserved IP) was not
   deleted** — that is the retention freeze through 6 Nov 2026, and `--full` refuses
   it before the date even when asked (§3, F7).
8. **Concurrent activity in the project**: `termini-node-c` was reconfigured and
   started by another workstream during this window, and a `termini-cap-probe-*` VM
   appeared and disappeared. Nothing captured here was affected (every mutation was
   name-filtered to `termini-verify*`), but the project is not frozen, so the raw
   snapshots reflect the moment they were taken.
